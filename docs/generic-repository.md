# The Generic Repository

A reusable data-access layer in the spirit of **EF Core / LINQ**: describe a table once and get the classic CRUD — `getAll`, `getById`, `insert`, `update`, soft delete, hard delete — plus a chainable query API, without writing SQL.

It ships with two interchangeable implementations behind the same interface:

| Driver | Implementation | Used when |
|--------|----------------|-----------|
| Oracle | `OracleGenericRepository` | `DATA_SOURCE=oracle` |
| In-memory | `MemoryGenericRepository` | any other `DATA_SOURCE` |

Both are exercised by the same tests and honour the same filter semantics, so a module developed against the in-memory driver behaves identically once you point it at Oracle.

---

## 1. Describe the entity

The domain model stays a plain interface. The mapping lives in infrastructure, in `src/infrastructure/repositories/entities.ts`:

```typescript
export const BRANCHES_ENTITY = defineEntity<IBranch>({
  table: ENTITY_NAMES.BRANCHES,
  primaryKey: "pkBranch",
  identity: true,                 // the DB generates the PK (IDENTITY)
  columns: {
    pkBranch:  { name: "PK_BRANCH", kind: "number", insertable: false, updatable: false },
    name:      { name: "NAME",       kind: "string" },
    available: { name: "AVAILABLE",  kind: "boolean" },
    createdAt: { name: "CREATED_AT", kind: "date", updatable: false },
    updatedAt: { name: "UPDATED_AT", kind: "date" },
  },
  softDelete: { property: "available", activeValue: 1, deletedValue: 0 },
  timestamps: { createdAt: "createdAt", updatedAt: "updatedAt" },
});
```

`columns` must cover every property of the model — TypeScript enforces it. This is the only place column names appear; renaming a column is a one-line change.

| Field | Meaning |
|-------|---------|
| `identity` | `true` (default): PK generated by the DB, recovered via `RETURNING … INTO`. `false`: the caller must supply it. |
| `insertable` / `updatable` | `false` for columns the database owns (identity PKs, `CREATED_AT`). |
| `kind` | Drives conversions: `boolean` ↔ `1/0`, `date` ↔ `Date`, `number`, `string`. |
| `softDelete` | Omit it and the entity simply has no logical delete. |
| `timestamps` | `createdAt`/`updatedAt` are written by the DB (`SYSTIMESTAMP`), not by the Node process clock. |

## 2. The contract

`IGenericRepository<T, TKey>` (`src/domain/interfaces/infrastructure/repositories/generic.repository.interface.ts`):

```typescript
getAll(options?)                    // lista
getPaged(page, limit, options?)     // { items, total, page, limit, pages }
getById(id, options?)
find(options)                       // filtro + orden + paginación
firstOrDefault(options?)
count(where?, withDeleted?)
exists(where, withDeleted?)

insert(entity)                      // devuelve la entidad con su PK
insertMany(entities)
update(id, changes)                 // devuelve la entidad, o null si no existe
updateWhere(where, changes)         // filas afectadas

softDelete(id)                      // borrado lógico
restore(id)                         // revierte el borrado lógico
hardDelete(id)                      // DELETE real
hardDeleteWhere(where)              // DELETE masivo

query()                             // API encadenable (ver §4)
```

Reads exclude logically deleted rows by default. Pass `withDeleted: true` to include them — the equivalent of EF Core's `IgnoreQueryFilters()`.

## 3. The filter language

Declarative, not stringly-typed. Every value travels as a **named bind**, and every column name is resolved through the entity mapping (an unmapped property throws), so user input never reaches the SQL text.

```typescript
// Igualdad directa
await branches.find({ where: { name: "Sucursal Centro" } });

// Operadores
await appointments.find({
  where: {
    fkBranch: 1,
    durationMin: { gte: 30, lte: 90 },
    status: { notIn: ["CANCELLED", "DONE"] },
    guestName: { ilike: "%walk-in%" },
    fkClient: { isNull: true },
    scheduledAt: { between: [from, to] },
  },
});

// Grupos anidados
await branches.find({
  where: {
    $or: [{ name: { ilike: "%norte%" } }, { address: { ilike: "%norte%" } }],
  },
});
```

| Operator | SQL |
|----------|-----|
| `eq` `ne` `gt` `gte` `lt` `lte` | `=` `<>` `>` `>=` `<` `<=` |
| `like` / `notLike` | `LIKE` / `NOT LIKE` |
| `ilike` | `UPPER(col) LIKE UPPER(:bind)` |
| `in` / `notIn` | `IN (…)` / `NOT IN (…)` — an empty list becomes `1 = 0` / `1 = 1` instead of invalid SQL |
| `between` | `BETWEEN … AND …` |
| `isNull` | `IS NULL` / `IS NOT NULL` |
| `$and` `$or` `$not` | Nested groups |

A bare `null` (`{ tag: null }`) means `IS NULL`.

## 4. The chainable API

`query()` returns an `IQueryable<T>` that mirrors LINQ: lazy, immutable, and only touches the database on a terminal operator.

```typescript
const page = await appointmentsRepository
  .query()
  .where({ fkBranch: 1 })
  .where({ status: "PENDING" })          // acumulativo: se combina con AND
  .orderByDescending("scheduledAt")
  .toPagedList(1, 20);

const exists = await branchesRepository.query().where({ name: "Centro" }).any();
```

Terminal operators: `toList`, `firstOrDefault`, `count`, `any`, `toPagedList`. Each chained call returns a **new** query, so a base query can be branched safely.

## 5. Module repositories

Per the project convention, a module gets the generic repository **plus** its own interface when it needs something the generic API cannot express:

```typescript
// Sucursales: el genérico basta.
export type IBranchesRepository = IGenericRepository<IBranch>;

// Citas: el genérico + un GROUP BY.
export interface IAppointmentsRepository extends IGenericRepository<IAppointment> {
  countByStatus(fkBranch?: number): Promise<AppointmentStatusCount[]>;
}
```

The implementation extends `BaseModuleRepository`, which delegates every generic method to the configured store and adds the error logging this project expects — no per-method `try/catch`:

```typescript
@injectable()
export class BranchesRepository extends BaseModuleRepository<IBranch> {
  constructor(
    @inject("BranchesStore") store: IGenericRepository<IBranch>,
    @inject("ILogger") logger: ILogger
  ) {
    super(store, logger, "BranchesRepository");
  }
}
```

For the extra SQL, `OracleGenericRepository.executeRaw()` is the documented escape hatch (aggregations, views, stored procedures). See `AppointmentsRepository.countByStatus`, which uses raw SQL on Oracle and computes the same result in JS for the in-memory driver.

## 6. Relations live in the service (`Include`)

A repository knows exactly one table. Composing across aggregates is a business decision, so it happens in the **service** layer — the equivalent of EF Core's `Include()`.

`loadRelated` (`src/application/queries/include.query.ts`) resolves a N:1 relation in **one batched query** (`WHERE key IN (…)`), not one per row:

```typescript
const branches = await loadRelated<IAppointment, IBranch>(appointments, {
  foreignKey: "fkBranch",
  relatedKey: "pkBranch",
  repository: this.branchesRepository,
});

const branchName = branches.get(appointment.fkBranch)?.name ?? null;
```

`withDeleted` defaults to `true` here: an appointment should still display its branch name after the branch is logically deleted.

## 7. Transactions (Unit of Work)

**Not everything is wrapped in a transaction.** A single statement is already atomic and travels with auto-commit; wrapping it would only add a round trip.

A transaction is opened when a use case writes in more than one place and a half-finished result would be invalid. That boundary is the service, not the repository:

```typescript
async hardDelete(id: number): Promise<boolean> {
  return this.unitOfWork.execute(async (scope) => {
    const branches = scope.repository<IBranch>(ENTITY_NAMES.BRANCHES);
    const appointments = scope.repository<IAppointment>(ENTITY_NAMES.APPOINTMENTS);

    // Las citas referencian la sucursal por FK: hay que borrarlas primero.
    await appointments.hardDeleteWhere({ fkBranch: id });

    if (!(await branches.hardDelete(id))) {
      throw new AppError("Branch not found", 404);   // provoca el rollback
    }
    return true;
  });
}
```

Inside the block, `scope.repository(...)` returns the same generic repository bound to the transaction's connection, so the service code is identical to the non-transactional path. Commit on success, rollback on throw, original error propagated.

- **Oracle** (`OracleUnitOfWork`): a real transaction on a single pooled connection with `autoCommit: false`.
- **In-memory** (`MemoryUnitOfWork`): snapshots each store before running and restores them if the block throws, so the dummy mode fails the same way. It does not provide isolation between concurrent operations — the database does.

## 8. Adding a new entity

1. Add the model interface in `src/domain/models/`.
2. Add its name to `ENTITY_NAMES` (`src/domain/models/entity-names.ts`).
3. Describe the mapping in `src/infrastructure/repositories/entities.ts` (and a seed in `seed-data.ts` for the in-memory mode).
4. Register the store and the unit-of-work entry in `src/core/di/repository.factory.ts`.
5. Declare `IXRepository = IGenericRepository<IX>` (plus extra methods only if you need them) and a `XRepository extends BaseModuleRepository<IX>`.
6. Write the service, controller and routes as usual.

Steps 1–5 contain no SQL. See **[docs/add-new-module.md](add-new-module.md)** for the full walkthrough.
